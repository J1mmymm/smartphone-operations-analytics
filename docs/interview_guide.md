# 面试讲解与追问准备

## 3 分钟讲解稿

这个项目来源于我之前的专业见习。当时我们以经营一家手机生产销售公司为背景，留下了 14 个经营回合的现金和产品回款记录。原始记录能说明每一回合花了多少钱、卖了多少钱，但不能系统回答销售增长、产能、库存、交付和现金之间的关系。

我先把 14 个回合映射成 42 个月，并锁定六个不能改变的控制量，包括销售回款 3,287.02 万元、L/H 产品回款、现金流入 5,013.07 万元、现金流出 4,977.74 万元和期末现金 35.33 万元。然后用固定种子补全 4 个 SKU、3 类渠道、4 个区域和 327 笔订单，保证每次生成一致，且所有明细汇总都能回到控制总额。

工具上，我用 Excel 做可审计分析，所有产品、渠道、库存和现金结果都由 `SUMIFS`、`COUNTIFS`、`XLOOKUP` 等公式从明细计算；用 MySQL 建星型模型和五个业务视图，通过 CTE、窗口函数、`LAG` 和排名做结构和趋势分析；最后用 Power BI 建三页看板，并用 23 个 DAX 指标统一口径。

最重要的发现是：最初“销售放量导致产能、仓储和资金全面失配”的假设只被部分支持。Q14 销售环比增长 33.33%，Q13、Q14 产能利用率达到 95.33% 和 91.39%，说明产能弹性很小；Q13 期末现金只剩 3,223 元，现金时点风险非常明显。但是数量履约率是 100%，累计缺货为 0，仓储占用率最高只有 27.69%，所以扩仓不是当前优先级。并且 Q14 在高产能利用率下，按时交付率回升到 95.31%，因此我没有把相关性写成因果。

最终建议是：建立 12 周滚动 S&OP，把 90% 产能利用率作为触发线；建立 13 周现金预测，把 30 万元作为情景安全底线，优化采购批次和账期；同时保护高毛利的 N-Lite，并分析 N-Plus 低毛利的价格、折扣和成本原因。

## 高频追问

### 1. 为什么要用 Excel、MySQL 和 Power BI 三套工具？

它们承担不同角色：Excel 最适合让业务人员逐格审计公式和修改情景假设；MySQL 负责稳定的数据结构、约束、复用视图和复杂查询；Power BI 负责统一 DAX 口径、交互筛选和管理层展示。三者的核心 KPI 必须对账，而不是分别算三套数字。

### 2. 明细数据不是完整业务系统导出，可信度如何保证？

我把“来源事实”和“补全维度”分开处理。销售、L/H 产品、现金流入/流出、期末现金和 14 季现金滚动是强控制量；订单日期、SKU、渠道、区域等明细用固定规则和随机种子补全。补全只能改变结构分布，不能改变控制总额。QA 会检查主键唯一、必填字段、金额数量逻辑、产品总额、现金总额和库存恒等式。

### 3. 为什么 Fill Rate 是 100%，还要看 On-time Order Rate？

Fill Rate 只说明最终发货数量覆盖了下单数量，不代表按承诺时间交付。这个项目中库存缓冲避免了缺货，但仍有约 7.95% 的订单发生延期，所以“有没有发出”和“是否按时发出”必须拆开。

### 4. 为什么 Ending Inventory 不能直接 SUM？

库存是快照指标。如果把多个月末库存直接求和，会把同一批库存跨月重复计算。DAX 先取当前筛选范围的最大月份，再计算该月库存；库存周转则使用月末库存金额的平均值作为分母。

### 5. 产能利用率高是否一定导致延期？

不一定。Q12、Q13 的按时率下降与高负荷同时出现，但 Q14 在 91.39% 产能利用率下按时率回升到 95.31%。这说明产能高负荷是风险信号，但排产、库存缓冲、加班和订单结构也会影响履约，现有数据不足以做因果识别。

### 6. 为什么不建议扩仓？

因为数据不支持。累计缺货为 0，数量履约率 100%，季度仓储占用率最高只有 27.69%。新增仓库会进一步占用现金，而当前更紧迫的是 Q13 现金低点和高产能利用率。应先优化 SKU 库存结构。

### 7. 现金风险是怎么发现的？

不只看期末现金，而是用窗口累计计算每个季度的 Closing Cash。全周期期末是 35.33 万元，看似为正；但 Q13 只有 3,223 元，说明企业曾经接近现金断点。再按用途拆分后发现原材料采购占流出 42.51%，因此建议优先调整采购批次、账期和回款节奏。

### 8. 哪个 SKU 最值得关注？

N-Lite 同时贡献 49.18% 销售额和 33.60% 毛利率，应保证供给和价格纪律。N-Plus 贡献 32.81%，但毛利率只有 20.05%，应建立价格—折扣—渠道返利—单位成本桥接，判断其规模是否真正创造价值。

### 9. 如果继续做，会增加什么数据？

优先增加客户/经销商应收账龄、供应商账期、SKU 预测与实际偏差、促销曝光和订单取消原因。这样可以把现金预测做成周粒度，把履约延迟拆成采购、生产、仓库和物流原因，并评估营销投入的增量效果。

### 10. 项目的局限是什么？

细分维度是基于经营流水的规则化补全，不是企业 ERP/CRM 全量导出；没有客户级回款、供应商级采购和营销触点，因此不能做客户留存、应收风险或营销因果分析。项目的价值在于展示可审计的数据工程和商业分析过程，而不是声称复原真实企业运营。

## 现场演示顺序

1. README：先讲问题和结论，强调“部分支持假设”。
2. Excel `质量检查`：证明数字可信；再看 `情景测算`。
3. MySQL `05_business_analysis.sql`：展示 CTE、`LAG`、排名和风险分层。
4. Power BI `经营总览`：点 Q13/Q14；再切到 `供应链与现金` 对照产能、履约与现金。
5. 收尾：给出三条建议，并主动说明数据边界。
